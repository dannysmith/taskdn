Taskdn is a plain-text task management system for individuals. Store your tasks, projects, and areas as markdown files with YAML frontmatter, then work with them through whichever interface suits your context: a desktop app for daily task management, a CLI for scripting and AI agents, an Obsidian plugin for knowledge workers, or a Claude Code skill for AI-assisted productivity.

The system is built on a simple principle: **your data is just files on disk**. Any tool that can read and write markdown files can work with your tasks. Taskdn products are interfaces optimized for specific contexts—not data silos.

## Core Concepts

Taskdn draws on GTD and PARA methods. Everything is stored as markdown files with YAML frontmatter—one file per entity. This means you own your data, can version it with git, edit it in any text editor, and build your own tools on top of it.

The products are **interfaces** to these files. The desktop app presents tasks in a polished UI optimized for doing and planning. The CLI provides programmatic access with output modes for humans, AI agents, and scripts. The Obsidian plugin lets you see task metadata while working in your notes. The Claude Code skill teaches Claude how to help you manage tasks effectively.

### The Hierarchy

Three entity types form a hierarchy:

- **Areas** are ongoing areas of responsibility (e.g., "Work", "Health", "Client: Acme Corp"). They never end.
- **Projects** are collections of tasks with a defined end goal. Projects optionally belong to an area.
- **Tasks** are small, actionable items. Tasks can belong to a project, an area directly, or stand alone.

This hierarchy lets you organize work naturally: an area like "Work" might contain projects like "Q1 Planning" and "Website Redesign", each with their own tasks. A task like "Call the dentist" might belong directly to your "Health" area without needing a project.

### Tasks

A task represents a single actionable item. Tasks live in your configured `tasks/` directory.

```yaml title="tasks/review-quarterly-report.md"
---
title: Review quarterly report
status: in-progress
scheduled: 2025-01-14
projects:
  - '[[Q1 Planning]]'
---
## Notes

Key points to review:
  - Revenue projections
  - Budget allocations
```

### Projects

A project represents a collection of related tasks with a defined end goal. Projects live in your configured `projects/` directory.

```yaml title="projects/q1-planning.md"
---
title: Q1 Planning
status: in-progress
area: '[[Work]]'
description: Quarterly planning and budget review for Q1 2025.
---
## Overview

This project covers all Q1 planning activities...
```

### Areas

An area represents an ongoing area of responsibility. Areas live in your configured `areas/` directory.

```yaml title="areas/work.md"
---
title: Work
description: Professional responsibilities and career development.
---
## Context

Current role, key responsibilities, and long-term goals...
```

## Using the Products

Each product serves a different context. You might use the desktop app for daily work, the CLI for weekly reviews with AI assistance, and the Obsidian plugin when you're deep in your notes.

### Desktop App

The desktop app is for day-to-day task management—a replacement for apps like Things or Todoist. It provides a polished interface for capturing tasks, planning your day, and working through your lists. Quick capture, keyboard shortcuts, and smart views help you stay focused.
