**Version:** 1.0.0-draft

This specification provides guidance for implementations that read, write, and present S1-compliant data.

## Design Principles

1. **Predictable over clever** — Users should predict what the implementation will do
2. **Explicit over silent** — Empty results should be explicit, errors informative
3. **Preserve user data** — Never discard data you don't understand

## Field Handling

### Canonical Names

Field names use kebab-case: `created-at`, `updated-at`, `defer-until`.

### The project/projects Convention

S1 defines `projects` as an array for compatibility, but Taskdn enforces single-project semantics:

- Display as `project` (singular)
- Accept `project` in input
- Read `projects[0]` from files
- Write `projects: ["[[value]]"]`

## Date Handling

| Field Type | Format | Example |
|------------|--------|---------|
| Date fields | `YYYY-MM-DD` | `2025-12-20` |
| Timestamp fields | `YYYY-MM-DDTHH:MM:SS` | `2025-12-15T14:30:00` |

## Writing Files

### Timestamp Management

| Event | Field | Action |
|-------|-------|--------|
| Task created | `created-at` | Set to current datetime |
| Task modified | `updated-at` | Set to current datetime |
| Status → `done`/`dropped` | `completed-at` | Set to current datetime |

### Atomic Writes

1. Write to temporary file in same directory
2. Sync to disk
3. Rename to target filename

## Default Semantics

### Active Items

**Tasks:** Status NOT IN (`done`, `dropped`, `icebox`), not deferred, not archived

**Projects:** Status NOT IN (`done`)

**Areas:** Status = `active` or unset

## Error Codes

| Code | When |
|------|------|
| `NOT_FOUND` | Entity doesn't exist |
| `AMBIGUOUS` | Multiple matches for fuzzy query |
| `INVALID_STATUS` | Bad status value |
| `INVALID_DATE` | Unparseable date |
| `PARSE_ERROR` | YAML malformed |
| `MISSING_FIELD` | Required field absent |
