# Task 5: Test vaults

Throwaway test vaults whose dates are always current, generated from templates. They replace `demo-vault/` and `dummy-demo-vault/`, give agents and dev builds something safe to point at (task 6), and become eval fixtures later (tasks 9 and 14).

## Background

- `demo-vault/` is a hand-written vault whose dates are frozen in January 2025, so the Today, overdue and this-week views show almost nothing. Its README and `AGENTS.md` disagree about its size (it actually has 9 areas, 18 projects, 102 tasks).
- `scripts/reset-dummy-vault.sh` copies it to the gitignored `dummy-demo-vault/` and symlinks the Obsidian plugin from `~/dev/obsidian-taskdn` into it.
- Only the CLI understands `TASKDN_MOCK_DATE`, so the desktop app and Obsidian can't be tested against old dates.
- Issue #26 asks for persona vaults generated by Claude, with a separate base repo.

## Design

**Templates with relative date tokens.** A template is a vault whose date fields use tokens such as `{{today}}`, `{{today+2d}}`, `{{today-1w}}` and `{{now-3d}}` (for datetimes). A small script renders a template into a real vault with concrete dates. It's deterministic and involves no LLM, and the output works the same in the desktop app, Obsidian, the CLI and Claude.

Things to decide while building it:

- **Token syntax.** Keep it minimal: `today` and `now` plus or minus days, weeks and months. Add weekday tokens (`{{next-fri}}`) only if a view needs them.
- **Where templates live.** Probably `test-vaults/<name>/`, committed, with a shared `.obsidian/` base (core plugins, Bases, the taskdn plugin enabled).
- **Where rendered vaults go.** One fixed absolute path outside the repo, e.g. `~/Library/Caches/taskdn/test-vaults/<name>/`, so that:
  - the sandbox can write there
  - every checkout and worktree, the desktop dev build and Obsidian all see the same path
  - a single env setting works everywhere (task 6)

  `--out` overrides it.
- **Pinned dates.** `--date 2026-11-15` renders as if it were that day, so eval runs are reproducible. That may make `TASKDN_MOCK_DATE` unnecessary.

## Work

- [ ] Renderer: `bun scripts/test-vault.ts render <template> [--out] [--date]`. It replaces tokens in frontmatter and bodies, writes a `.taskdn.json` into the rendered vault, symlinks the local Obsidian plugin as the reset script does, and prints the `obsidian://` link. Unit tests for token parsing and date maths.
- [ ] Convert `demo-vault/` into a template, keeping its coverage and giving it current-relative dates.
- [ ] Edge-case template: bad YAML, unknown statuses, an unquoted `[[wikilink]]`, a scalar `project:`, broken and ambiguous links, a title that differs from its filename, non-ASCII titles, unknown fields, and the three directories in unrelated locations. This one is for the CLI's `doctor`, the spec work and `tdn-core`'s conformance tests.
- [ ] A coverage checklist in the templates' README. Every template should state which of these it covers: every task and project status, overdue, due today, scheduled today, deferred until today, deferred to the future, blocked projects, archived tasks and areas, orphan tasks, aliased wikilinks, and one large vault for performance.
- [ ] Replace `demo-vault/`, `dummy-demo-vault/` and `scripts/reset-dummy-vault.sh`. Update `package.json` scripts (`demo:reset`, `demo:import-to-things`), `AGENTS.md`, `CLAUDE.md` files and anything else that mentions them.
- [ ] Persona generator (#26): a repo skill (`.claude/skills/generate-test-vault/`) that has Claude write a template for a persona and size using the same tokens, plus `persona.md` and a `playbook.md` of things to try. It then renders the template and runs `tdn doctor` against it. Use the persona knobs from the issue. Drop the issue's separate base repo; the shared `.obsidian/` base in this repo replaces it. Generated templates can be committed when they're worth keeping as fixtures. This can be a second session.

## Done when

`bun scripts/test-vault.ts render demo` produces a vault in which the desktop app's Today, overdue and newly-available views all have content, whatever today's date is. The edge-case template exists, the old demo vault and its reset script are gone, and the docs point at the new setup.
