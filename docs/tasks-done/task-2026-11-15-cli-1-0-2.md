# Task 4: CLI 1.0.2

Fix the CLI's data bugs that affect daily use now. The CLI gets a full redesign later (2.0), so this is fixes only: no refactoring, no new features. Danny and `obsidian-inbox-assistant` use 1.0.1 every day.

Evidence for each bug is in `docs/tasks-todo/temporary/cli-evidence/`.

## Fixes

- [x] **`--json` output can't be parsed.** `formatOutput` in `tdn-cli/src/output/index.ts` prefixes every output mode with an ANSI reset (`reset.open`), so `tdn list --json | jq` fails. Only human output to a TTY should get colour codes. `obsidian-inbox-assistant` strips them today (`src/assess/context.ts:77`); that can stay as it is.
- [x] **`new --dry-run` writes the file.** The option is declared in `tdn-cli/src/commands/new.ts` and never read. Make it preview without writing, as `update` and `set` do.
- [x] **Timestamps are written three different ways.**
  - `tdn-cli/crates/core/src/writer.rs` writes UTC with `Z`.
  - `tdn-cli/src/commands/set.ts` writes `new Date().toISOString().slice(0, 19)`: UTC with no zone, which S1 says to read as local time. So `completed-at` is wrong whenever local time isn't UTC.
  - `tdn-cli/src/commands/append-body.ts` stamps the UTC date, which is wrong near midnight.

  Make all three write local time with its offset (`2026-11-15T14:30:00+00:00`), and the local date where only a date is written. Check that S1's wording allows offsets; Spec 1.1 (task 8) will pin it down.

  - **Correction:** `set status` never wrote that format. Real status changes go through the Rust writer; the `toISOString()` was only in the `--dry-run` preview, which is where the evidence came from.
  - **Done:** the Rust writer, the `set status` preview and `append-body` all use local time (or the local date) now. S1 already allows offsets ("MAY be present… MAY ignore timezone information when displaying"), and a tool that ignores the offset still shows the right local time, which wasn't true of `Z`.
- [x] **The skill and website teach a command that fails.** `tdn show "Title"` treats the title as a path. It appears in `tdn-claude-plugin/skills/task-management/` (`SKILL.md`, `examples.md`, `command-reference.md`, `decision-guide.md`) and in `website/src/content/docs/cli/` (`read-commands.mdx`, `working-with-ai.mdx`). Replace each with a command that works, checked against a test vault. The skill is rewritten in task 14, so keep the change minimal.

Each fix gets a focused test.

- `--dry-run` for `new`: the Rust create functions take an optional `dry_run` and parse the would-be content in memory (the file parsers were split into read + parse). JSON output reports `dryRun: true`, like `update`.
- The ANSI bug was invisible to tests because `runCli` strips ANSI from all output. It now also returns `rawStdout`, which the new test checks.
- Also fixed: `tdn show --help` claimed it took a name, and the skill's command reference passed `show` a second argument, which errors. The plugin is bumped to 0.1.4 for the skill changes.

## Not in this release

- Files with an unknown status or an unquoted wikilink are silently dropped. That's a spec question (task 8) and gets fixed in `tdn-core`. Include a small fix here only if Danny has hit it in real use.
- Lookup inconsistencies, unvalidated references and the duplicate formatters are all for the 2.0 redesign. One more for that list, from review: `context task` treats any argument containing `/` as a path, so a title like "CI/CD rollout" can't be looked up by title.
- From review, fixed here: `list --sort created|updated` compared timestamps as strings, which misorders values with different offsets (`…Z` from older files, `…+01:00` from new ones). Those two fields now sort by the instant they represent.
